# The API

Ten routes. The console is the only client, but everything it does is available to you.

Base URL when running locally: `http://localhost:8000`
Interactive docs, generated by FastAPI: `http://localhost:8000/docs`

---

## Conventions

**JSON everywhere.** Content type `application/json`.

**Errors come back as JSON too**, not as HTML, with `error` holding a message and `trace` holding
the last part of the stack trace. So a failing request is still parseable.

```json
{ "error": "RuntimeError: memory engine not connected", "trace": "..." }
```

Some routes return HTTP 200 with an `error` key in the body, because the failure happened in a
background thread that could not change the status code. Check for the key, not just the status.

**Calls that touch memory are slow.** Budget four to five seconds for a triage, a few hundred
milliseconds for a recall, two to four minutes for a cold seed.

## `GET /api/state`

Is it up, is it seeded, what went wrong. Call this first.

```bash
curl -s localhost:8000/api/state | python3 -m json.tool
```

```json
{
  "mode": "Hindsight Cloud",
  "seeded": true,
  "seeding": false,
  "progress": { "stage": "ready", "pct": 1.0, "detail": "" },
  "error": null,
  "bank_incidents": "faultline-incidents",
  "bank_team": "faultline-team",
  "corpus": { "incidents": 19, "services": 10, "open_actions": 19 }
}
```

| Field | Meaning |
| --- | --- |
| `mode` | `Hindsight Cloud` or `Hindsight (embedded)`. Shown in the top right of the console |
| `seeded` | Whether the corpus is loaded |
| `seeding` | Whether it is loading right now |
| `progress` | Current stage, 0 to 1, and a detail string like `12/19` |
| `error` | Last failure, or `null` |

## `POST /api/setup`

Creates the banks, installs the directives and mental models, and loads the corpus.

**Idempotent.** If the banks already exist and already have memories, it reports that and skips the
seeding rather than duplicating everything.

| Query | Default | Meaning |
| --- | --- | --- |
| `force` | `false` | Delete both banks and rebuild from scratch. **Needed after you change the corpus**, otherwise old memories linger and corrupt the measurement |

```bash
curl -X POST "localhost:8000/api/setup?force=true"
```

Returns `{"status": "started"}` immediately. It runs in a background thread, so poll
`/api/progress`.

---

## `GET /api/progress`

Seeding progress.

```json
{
  "progress": { "stage": "retaining incidents", "pct": 0.63, "detail": "12/19" },
  "seeding": true,
  "error": null
}
```

Stages, in order: `creating banks`, `retaining incidents`, `retaining service state`,
`retaining remediation backlog`, `consolidating observations`, `measuring`, `ready`. Or `failed`,
in which case `error` has the message.

## `GET /api/corpus`

The whole dataset, as JSON. No memory required, so it works even before seeding.

```bash
curl -s localhost:8000/api/corpus | python3 -m json.tool | head -40
```

Returns `org`, `services`, `incidents`, `open_actions`, `service_state`, `live_alert`, `clusters`,
`cluster_labels`.

Use this if you want to write your own analysis, build a different demo, or check exactly what the
agent is being asked about.

## `POST /api/triage`

The main event.

```json
{ "with_memory": true }
```

| Field | Default | Meaning |
| --- | --- | --- |
| `with_memory` | `true` | `false` runs the identical query against the empty control bank |

```bash
curl -X POST localhost:8000/api/triage \
  -H 'content-type: application/json' \
  -d '{"with_memory":true}'
```

```json
{
  "alert": { "...": "the live alert" },
  "payload": {
    "verdict": "The payout-worker is suffering an IAM authorization failure...",
    "fingerprint_match": 100,
    "matched_incident_ids": ["INC-1042", "INC-1188"],
    "failure_mode": "IAM Authorization Denials",
    "root_cause_hypothesis": "Wildcard trust policy Principal={\"AWS\": \"*\"}...",
    "state_key": "iam_role_trust_policy",
    "first_actions": [
      { "step": "Replace wildcard Principal with explicit role list",
        "detail": "Update the shared Terraform module",
        "runbook": "RB-07" }
    ],
    "recurrence_risk": [
      { "service": "inventory-sync", "severity": "SEV2",
        "why": "Still carries the iam_role_trust_policy condition",
        "evidence": "CURRENT INFRASTRUCTURE STATE - iam_role_trust_policy, last audited 2026-01-14" }
    ],
    "stale_action_items": [
      { "text": "Conduct a fleet-wide sweep...", "owner": "Marcus Feld",
        "incident_id": "INC-1042", "times_written": 2 }
    ],
    "confidence": "high",
    "raw": "the model's unformatted reply"
  },
  "recalled": [ { "text": "...", "type": "observation", "score": 0.87 } ],
  "mental_models": { "failure-fingerprints": "...", "recurrence-risk": "...",
                     "open-remediation": "..." },
  "trace": { "query": "...", "recalled": 8, "mental_models_consulted": ["..."] },
  "baseline": "",
  "with_memory": true
}
```

Notes worth knowing:

- `payload.recurrence_risk` is built from the recorded infrastructure state, not from the model. The
  model supplies only `why`. See [HOW_IT_WORKS.md step 5](HOW_IT_WORKS.md).
- `payload` fields degrade to empty rather than erroring. A partial answer is still worth returning
  during an outage.
- `baseline` is populated only when `with_memory` is `true`, so you can show both in one request.
  With `false`, `payload` is empty and `baseline` holds the answer.
- `raw` is the model's unparsed output. Useful when you want to check whether a field failed to
  parse.

## `POST /api/resolve`

Records the outcome of the live incident and refreshes the fingerprints. This is what closes the
loop.

Every field is optional. Omit them all to use the defaults from `app/corpus.py`.

```json
{
  "root_cause": "optional, overrides the default",
  "resolution": "optional",
  "runbook": "optional",
  "action_items": [ { "owner": "...", "text": "...", "status": "open", "note": "..." } ]
}
```

```bash
curl -X POST localhost:8000/api/resolve -H 'content-type: application/json' -d '{}'
```

Returns `{"status": "retained", "incident_id": "ALR-4471"}`.

It retains the incident into `faultline-incidents`, retains each open action into `faultline-team`,
and asks Hindsight to rewrite the mental models.

Run it, then triage again, and the count on the repeated action goes up and a new action appears.
That is the system learning from its own experience.

## `GET /api/learning-curve`

The measured recall against the answer key. Cached after the first call.

```bash
curl -s localhost:8000/api/learning-curve | python3 -m json.tool
```

```json
{
  "overall_recall": 0.8333,
  "true_positives": 5,
  "possible": 6,
  "incidents_measured": 5,
  "curve": [ { "at": "2026-05-30T02:41:00Z", "incidents_indexed": 1,
               "cumulative_recall": 1.0 } ],
  "per_incident": [
    { "incident_id": "INC-1219", "service": "inventory-sync",
      "cluster": "third_party_no_backoff_or_timeout",
      "expected": ["INC-1211"], "found": [], "missing": ["INC-1211"],
      "recall": 0.0 }
  ],
  "clusters": { "iam_stale_trust_policy": { "members": ["INC-1042", "INC-1188"],
                                           "label": "Stale IAM role trust policy" } }
}
```

`curve` is what the chart draws. `per_incident` is the table, including the miss.

Costs a handful of `recall` calls, all local ranking, so it is cheap to call.

## `GET /api/mental-models`

The three standing answers, as text.

```bash
curl -s localhost:8000/api/mental-models | python3 -m json.tool
```

Keys: `failure-fingerprints`, `recurrence-risk`, `open-remediation`. A key is absent if that model
has not been written yet, which happens for a minute or two after a fresh seed while consolidation
runs. That is normal.

---

## `GET /api/memories`

Inspect raw memory, or run a live search.

| Query | Default | Meaning |
| --- | --- | --- |
| `limit` | `60` | Maximum items, for browsing |
| `q` | none | If present, runs `recall` with this query instead of listing |

```bash
# search
curl -s "localhost:8000/api/memories?q=wildcard%20trust%20policy" | python3 -m json.tool

# browse
curl -s "localhost:8000/api/memories?limit=20" | python3 -m json.tool
```

Items come back as `{"text": "...", "type": "world|experience|observation", "score": 0.87}`. The
`type` tells you whether it is a raw fact, something the bank did, or a consolidated belief.

## Calling it from your own code

```python
import requests

BASE = "http://localhost:8000"

requests.post(f"{BASE}/api/setup").raise_for_status()

r = requests.post(f"{BASE}/api/triage", json={"with_memory": True}).json()
p = r["payload"]

print(p["fingerprint_match"], p["matched_incident_ids"])
for risk in p["recurrence_risk"]:
    print("still exposed:", risk["service"])
for action in p["stale_action_items"]:
    print(f"promised {action['times_written']}x:", action["text"])
```

Swap `app/corpus.py` for your own incidents and this becomes a working internal tool. See
[DATA.md](DATA.md) for the field list and the steps to re-seed.
