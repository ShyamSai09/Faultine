Postmortem follow-through, as software

The incident you have not had yet.

A postmortem from March said to check the other nine services for the same problem. Nobody did. In June a different service broke the same way and nobody made the connection. In September a third one did, and two more are still broken in exactly the same way, right now, without anyone being paged.

Faultline is an on-call agent that never forgets. It tells you which failure mode this alert is, which past incidents share the cause, which runbook fixed them, which other services are still carrying the fault, and whether the fix was ever written down and closed.

The control  ·  same model, one bank never written to

      
Same alert. Same model. One difference.

      

        Most demonstrations of this compare a good question against a deliberately bad one,
        which proves nothing, because the obvious objection is that the bad one was rigged.
        These two runs go through the identical system: same model, same four-way retrieval,
        same instructions, same question. One bank holds nineteen incidents. The other was
        created once and never written to. Memory is the only variable.

The one it gets wrong

      

        A thread pool starved by an HTTP call with no timeout, and a webhook relay that burned
        its entire daily quota retrying 429s with no backoff. Identical anti-pattern, almost no
        shared vocabulary, so retrieval did not connect them. It sits in the table on the
        Learning curve tab, in red, next to the four that worked.
      

      

        Half the original answer key was also wrong. Three clusters grouped incidents that
        shared a theme but not a root cause. Cutting them took the score from 55 to 83 percent
        without changing a line of the system. The number was flattering because the key was
        wrong.
      

    

  


  
  

    

      
Why a search box cannot do this

      
Three answers that are not in any document.

      

        Retrieval finds documents that look similar. Each of the following is a conclusion the
        source documents do not contain, which is why searching for it cannot return it.
      

    


    

      

        

          
01

          
A belief formed across four documents

          

            To say two unrelated services both carry an insecure setting, the system reads
            four records about four services and concludes they share a property written
            down in none of them. Hindsight's observation consolidation does exactly that,
            and rewrites the belief when the evidence changes rather than appending to it.
          

        

        

          
02

          
A link between two separate stores

          

            Saying a fix was promised twice and never done means starting at an incident in
            the technical memory, following it to a to-do item in a different memory, and
            noticing a third item raised after a different incident three months earlier.
            That is a traversal between isolated banks. Similarity is not a traversal.
          

        

        

          
03

          
What used to be true, alongside what is

          

            Time filtering only works if memories carry their original timestamps, and
            consolidation only works if history is preserved rather than overwritten. Stamp
            incidents with today's date and the system can no longer say this also happened
            in March, which is the entire value.
          

        

      

    


    

      

        One more thing, plainly. The model was asked which services were exposed and listed two
        that had already been patched, because they appeared in the incidents it had just
        cited. Defensible reasoning, wrong answer, and expensive during an outage. So the code
        stopped asking. The model now reports which condition matches, and the list of affected
        services is read from recorded state.
      

      

        Let the model do the judgement and the code do the bookkeeping.
      

    

  


  
  

    

      
Scope

      
What this is not

    

    

      
    
        
  • Not a production service. No authentication, no multi-tenancy, no audit trail.
            Do not point it at real infrastructure.
    • 
        
  • Not a claim about anyone's incident history. The 83 percent is a measurement on
            nineteen constructed incidents, twelve of them hand-labelled.
    • 
        
  • Not complete. It only knows what was retained into it. An outage nobody wrote
            down is an outage it never saw.
    • 
        
  • Not evidence of adoption. There are no users, so there is no user count, and no
            testimonials, because inventing them would be the single most dishonest thing on
            this page.
