# Anti-slop audit 001

**Date:** 28 September 2026
**Scope:** the whole interface, the previous dark build and the current rebuild
**Ruleset:** antislop core, 38 rules
**Mode:** audit, then fix

Findings are numbered and never renumbered. Each cites the rule it breaks and one line of
evidence. Priority follows the rule tier: Hard Gate is HIGH, Purpose-Gate is MEDIUM, Quality Locks
is LOW.

All findings below are **closed**. The evidence for each is re-verified at the bottom of this file.

---

## Findings

### 1. `--fg-faint` failed contrast on every surface — R-25 — HIGH — CLOSED

`#5f6b83` measured 3.69:1 on `--bg`, 3.55 on `--bg-1`, 3.38 on `--bg-2`, 3.18 on `--bg-3`. WCAG AA
needs 4.5:1 for normal text. It was the second-most-used colour in the build, on around fifteen
selectors: every column heading, every block label, every table header, the gauge caption, the
empty state, the hint text, the axis labels. Nearly all of the interface's small text failed AA.

**Fixed** by rebuilding the palette from the ratios backwards rather than adjusting one value.
`--ink-3` is now `#5F5B52`, measured at 5.89:1 on paper, 5.38 on the sunken surface, 5.63 on the
finding wash. Fifteen pairings now pass, worst case 5.38:1.

### 2. `--line` used as a focus ring — R-25, R-32 — HIGH — CLOSED

`#1f2634` measured 1.31:1 against the background. It was the border on every card, table and panel.
For a meaningful non-text boundary WCAG needs 3:1, and a focus indicator is explicitly a non-text
element. The previous build had a focus ring on exactly one control, and it was a soft `box-shadow`
in the same failing colour family.

**Fixed** by separating the two roles that were conflated. `--rule` is decorative hairlines only
and is exempt. Interactive boundaries use `--edge` at 8.07:1. Focus is a 2px `--ink` outline with a
2px offset, visible on paper, on the sunken clipping surface and on the red wash, declared once for
every focusable element.

### 3. Em dashes throughout the interface — R-02 — HIGH — CLOSED

Fifteen in `index.html` and `app.js` at last count: in the page title, in the memory switch label,
in section copy, in the button subtitle.

**Fixed.** Zero in `landing.html`, `index.html`, `app.js` and `landing.js`, verified by grep.
Rewritten with commas, colons and parentheses, which read better anyway.

### 4. Background grid — R-07 — MEDIUM — CLOSED

A 48px `linear-gradient` grid over `body::before`. Listed as slop with no stated purpose, and it
had none: it was a "tech" default.

**Removed.** Zero `linear-gradient` in any stylesheet now. Structure comes from hairlines and from
the sunken surface used for pasted log output.

### 5. Glow on three elements — R-13 — MEDIUM — CLOSED

`box-shadow` glow on the wordmark, on the risk indicator dot, and on the toast. The dose cap is one
or two focus accents.

**Removed entirely.** Zero `box-shadow` and zero `backdrop-filter` in any stylesheet. The toast
uses a hairline and a red border, which is more legible than a shadow on a light background anyway.

### 6. Capsule badges combining four slop signals — R-09 — MEDIUM — CLOSED

`.pill` was a pill shape, plus a thin border, plus uppercase, plus a glow, and it appeared on every
status in the interface.

**Fixed** by replacing the pill with a `.status` component: a 7px square in mono type, beside a
label, with a rule when a rule is warranted. A status now says what it is instead of glowing.

### 7. Inter and JetBrains Mono, with no reason — R-06 — MEDIUM — CLOSED

The two typefaces the model reaches for by default, chosen for no stated reason. `JetBrains Mono`
in particular was doing no work: it was decorative terminal aesthetics on a page that is about
reading documents.

**Fixed** by picking a pair with a division of labour and a written reason: **Newsreader**, a
transitional serif, because a postmortem is a written document and is set in a reading face; and
**IBM Plex Mono**, drawn by IBM for technical documentation, which is what a log excerpt is. The
rule is enforced in the markup: agent prose is set in Newsreader, the alert and logs in Plex Mono.
That typographic split is the product's thesis rendered as a font decision.

### 8. Identical card rows — R-14, R-05 — MEDIUM — CLOSED

The learning-curve metrics were four identical cards. So were the corpus stats. Copy-paste layout
with no hierarchy.

**Fixed** by rebuilding the page sections on the ruled gutter: a narrow metadata column carrying
dates, ids and factual notes, and a body column. Section composition now varies by content, which
is the intent of the RHYTHM 2 dial. The metrics use a divided definition row, not four cards.

### 9. Font pairing and palette size — R-29 — LOW — CLOSED

Five accent colours in the previous build (amber, red, green, cyan, violet) against a
"max 2 to 3 core plus 1 accent" limit.

**Fixed.** Two neutrals, one accent. Deliberately absent: green. A postmortem does not tick things
green, and adding a success colour would turn a document into a status dashboard, which is the
thing this design argues against. "Resolved" is expressed by the absence of red, a weight change,
and a hairline.

### 10. No focus indicators on most controls — R-32 — HIGH — CLOSED

Two `focus-visible` rules in the whole stylesheet. Tabs, mental-model tabs, the memory search, and
the table navigation were keyboard-invisible. Tabs were `<div>`s with a click handler, so they were
not reachable by `Tab` at all.

**Fixed** by converting tabs to real `<button role="tab">` with `aria-selected`, the tablist to
`role="tablist"` with arrow-key navigation, the mental-model tabs to the same pattern, and adding
one `:focus-visible` rule covering every focusable element. Skipping a link in the header works
because the element is a real anchor.

### 11. No error state — R-27 — HIGH — CLOSED

Triage failure showed a toast that disappeared after five seconds, and the empty state was reused
to carry the error text. During an outage, a disappearing error is the worst possible behaviour.

**Fixed** with three designed states on the answer panel: a dashed empty state, a loading state
naming the current step, and a persistent bordered error panel showing the real message.

### 12. Invented wordmark with no disclosure — R-23, R-38 — MEDIUM — CLOSED

A geometric mark was invented and presented as finished.

**Fixed** by replacing it with the product name in the chosen typeface with a red initial, and
serving a single-glyph favicon as SVG. `DESIGN.md` states both are provisional until a human
confirms one.

### 13. Dark mode as an unargued default — R-21 — MEDIUM — CLOSED

Dark was chosen because it looks technical. That is exactly the reasoning the rule rejects.

**Reconsidered and changed.** The build is now a printed report: warm off-white, warm near-black,
serif prose. `DESIGN.md` records the competing argument (dark for a 3am on-call console is real),
why it lost (the product argues that reading matters more than alerting, and paper wins on
contrast and legibility), and that the trade should be revisited if night use proves it wrong.

### 14. No design direction — R-37 — HIGH — CLOSED

There was no `DESIGN.md`, so the previous build was a directionless draft.

**Fixed** by writing `DESIGN.md` with the idea, a one-line reason for every value, the three dials,
the rejected alternatives, and the author's own caveat that an agent-chosen aesthetic skews toward
the default taste these rules exist to filter. That caveat is at the top of the file, not buried.

### 15. Development patched stylesheets with string replacement — R-33 — MEDIUM — CLOSED

Features were added during the build by running Python that rewrote `web/app.js` and
`web/styles.css`. Nothing shipped (no patch scripts are in the repository, verified) but the
practice leaves the source as a patchwork.

**Fixed** by rewriting both files in source for this pass. The stylesheet is now three files split
by role, and the markup is hand-written. No patch script remains.

### 16. Learning-curve chart contradicted its own heading — C-3 — MEDIUM — CLOSED

The page was titled "the memory gets better, measurably" above a curve that visibly dips, because
a harder pair enters the denominator. That reads as a bug.

**Fixed** by retitling to what the chart measures, "does the memory actually connect these
incidents", and writing the dip into the caption, including naming the miss and the answer-key
correction.

### On the mobile check

The first pass looked badly broken, and I recorded it as a Hard Gate failure. It was not. Chrome
headless enforces a minimum window width, so a 390px screenshot was a crop of a wider render. The
real check loaded the console in a 390px iframe and measured every element's bounding box against
the viewport: 0 overflowing, `documentElement.scrollWidth` equal to 390. The only genuine mobile
defect was the four tabs wrapping onto a second row, which is now fixed by tightening their padding
at 620px.

Worth stating plainly, because the first version of this section would have said otherwise: I
reported a failure that was an artefact of my own test harness. The gate is only useful if the
evidence is right, and "I checked" is not the same as "it passed".

### Not checked

- The 2px focus ring was verified by inspection of the contrast ratio, not by tabbing through

- No real user has looked at any of this. The liveliness question in particular is the one I am
  least entitled to settle alone, which is why `DESIGN.md` is written to be argued with.
